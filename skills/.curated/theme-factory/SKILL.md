# Theme Factory

## Overview

Use this skill when the work needs a coherent visual system rather than one-off styling choices. A theme should define mood, colors, typography, and best-fit contexts clearly enough that it can be applied across an artifact without constant re-decisions.

## Workflow

1. Identify the artifact type, audience, tone, and constraints.
2. Read `references/theme-index.md` to compare the available presets.
3. Choose one of the preset themes or create a custom theme when none fit.
4. Load only the selected theme file from `references/`.
5. Apply the theme consistently: headings, body text, accents, backgrounds, and emphasis styles should all follow the same system.
6. Check contrast, legibility, and whether the theme matches the artifact's job.

## Theme Rules

- Keep type roles simple: display, heading, body, optional mono or label style.
- Use a limited palette with one primary accent and clear neutrals.
- Let the theme support the content; do not sacrifice clarity for novelty.
- Preserve strong contrast, especially in slides and documents that may be projected or printed.
- When adapting a theme to HTML or product surfaces, translate the system rather than copying document-specific quirks.

## Creating A Custom Theme

When the presets are not a fit, create a custom theme with:

- Name
- One-sentence mood statement
- Color palette
- Typography pair
- Best-use guidance
- Notes on contrast or layout behavior

Match the structure of the preset reference files so the custom theme can be reused.

## Deliverables

- The selected theme name and why it fits
- The applied artifact or styling guidance
- Any custom theme definition created during the task
